## What changes

Additive, forward-only. Introduces Stripe payment rail and Connect Express seller onboarding.

### New enum
- `payment_status`: `PENDING`, `SUCCEEDED`, `FAILED`, `REFUNDED`, `DISPUTED`, `PARTIALLY_REFUNDED`

### Columns added to `orders`
- `payment_intent_id text` — Stripe PaymentIntent id (nullable for cash/offline orders)
- `payment_status public.payment_status` — derived from webhook events
- `paid_at timestamptz` — set by webhook on first success

### New tables
1. **`payments`** — immutable payment records written ONLY by the webhook
   - `id uuid PK`
   - `order_id uuid not null references orders(id) on delete cascade`
   - `stripe_payment_intent_id text not null unique`
   - `amount_cents integer not null check (amount_cents >= 0)`
   - `status public.payment_status not null`
   - `metadata jsonb` — raw Stripe event payload
   - `created_at timestamptz not null default now()`
   - Index on `(order_id)` and `(stripe_payment_intent_id)`

2. **`payout_accounts`** — seller Stripe Connect accounts
   - `id uuid PK`
   - `user_id uuid not null unique references profiles(id) on delete cascade`
   - `stripe_account_id text not null unique`
   - `onboarding_status text not null` — `PENDING`, `ENABLED`, `RESTRICTED`, `DISABLED`
   - `payouts_enabled boolean not null default false`
   - `details_submitted boolean not null default false`
   - `metadata jsonb` — cached Connect account data
   - `created_at timestamptz not null default now()`
   - `updated_at timestamptz not null default now()`
   - Index on `(user_id)` and `(stripe_account_id)`

3. **`webhook_deduplication`** — at-least-once delivery guard
   - `id uuid PK`
   - `stripe_event_id text not null unique`
   - `processed_at timestamptz not null default now()`
   - Index on `(stripe_event_id)`

### RLS policies
- `payments`: service-role INSERT only; buyers/sellers can SELECT their own via order
- `payout_accounts`: users can SELECT their own row; service-role INSERT/UPDATE
- `webhook_deduplication`: service-role only (no client policies)

### Edge Functions (deployed)
- `payments-config` — GET returns `{ publishableKey, configured }`
- `payments-create-intent` — POST creates/reuses PaymentIntent for an order
- `stripe-webhook` — POST verifies signature, dedupes, mutates orders/payments
- `connect-onboarding` — POST generates Connect Express onboarding link

## Why

WEB-006 requires a shared payment backend for both web admin finance UI and mobile checkout. Stripe Connect Express runs seller KYC and payouts (no custom KYC build). The webhook is the source of truth for payment state — clients never flip `payment_status` directly. Idempotent PaymentIntent creation prevents duplicate charges on retry.

## RLS intent

- `payments`: buyers/sellers read only their own payments (via order_id). No client writes.
- `payout_accounts`: a user reads only their own Connect row. Service role writes from webhook/onboarding.
- `webhook_deduplication`: invisible to clients; service-role only.
