# SCR-001 — Core marketplace schema: profiles, categories, listings, photos, favorites, saved_searches

Status: Accepted
Date: 2026-06-22
Author: platform
DB reviewer: web lead
Migration: supabase/migrations/20260622120000_scr001_core_schema.sql

## What changes

Additive, forward-only. The first real schema. Adds:

**Extensions**: `postgis` (radius/distance search — see ADR-0001).

**Enums** (native, values match shipped mobile `api.ts`):
- `listing_type` = VENTE | LOCATION | SERVICE
- `listing_status` = DRAFT | ACTIVE | PAUSED | SOLD | ARCHIVED
- `user_status` = ACTIVE | PENDING | SUSPENDED | BANNED
- `kyc_status` = UNVERIFIED | PENDING | VERIFIED | REJECTED
- `listing_condition` = new | likenew | good | fair

**Tables**:
- `profiles` — `id uuid PK references auth.users(id) on delete cascade`, display
  fields (display_name, avatar_path, bio, age, profession), private location
  (address_label, lat, lng) + `location geography(Point,4326)` generated, public
  location (neighborhood, city), account state (`status`, `kyc_status`,
  `kyc_tier`), counters (rating, reviews_count, listings_count, sales_count,
  gmv_cents), timestamps.
- `categories` — flat self-referencing tree: `id uuid PK`, slug, label, subtitle,
  `parent_id`, `type listing_type`, glyph, sort_order, `unique(type, slug)`.
- `listings` — owner_id→profiles, listing_type, title, description, category_id,
  condition, per-type pricing (price_cents | price_per_day/week/deposit_cents |
  hourly_rate/flat_rate_cents + service_radius_km), lat/lng + generated
  `location geography(Point,4326)`, neighborhood, `status`, counters
  (view_count, favorites_count), timestamps.
- `listing_photos` — id, `listing_id` (cascade), storage_path, sort_order,
  created_at.
- `favorites` — `PK (user_id, listing_id)`, both cascade.
- `saved_searches` — id, user_id, name, query, listing_type, category_id,
  condition, min/max_price_cents, center_lat/lng + generated `center geography`,
  radius_meters, alerts_enabled, created_at.

**View**: `public_profiles` (security-definer) exposing only the neighbour-safe
columns (display_name, avatar_path, bio, age, profession, neighborhood, city,
rating, reviews_count, listings_count, sales_count, created_at).

**Constraints**: per-type pricing CHECK that fires only for non-DRAFT listings
(an ACTIVE VENTE must have price_cents; LOCATION → price_per_day_cents; SERVICE →
hourly_rate_cents or flat_rate_cents). Non-negative money checks.

**Triggers**: `favorites` insert/delete maintains `listings.favorites_count`;
`updated_at` touch triggers.

**Indexes**: `listings(status, listing_type, category_id)` partial on ACTIVE,
`listings(owner_id, status)`, GIST on `listings.location` + `saved_searches.center`,
`favorites(listing_id)`, `categories(type, parent_id, sort_order)`.

**Storage**: buckets `listing-photos` + `avatars`, both public-read; write RLS
scopes each member to their own path prefix.

**Seed**: VENTE category taxonomy from mobile `categories.ts` (LOCATION/SERVICE later).

## Why

Unblocks the mobile consumer chain (profiles, public discovery, listing authoring)
and the web admin read models. Board: **WEB-003**. The enum values, profile
public/private split, per-type pricing, and category tree are dictated by the
already-shipped mobile contract (`fethi-mobile/src/shared/lib/api.ts`); this SCR
makes the database match it. Design grilled via `grill-with-docs`; geo decision in
ADR-0001; domain language in `CONTEXT.md`.

## RLS intent

- `profiles`: base table owner-only (`(select auth.uid()) = id`) for SELECT/UPDATE;
  INSERT own row on signup; staff access via service-role only. Exact coords + KYC
  never anon-readable.
- `public_profiles` view: SELECT granted to `anon` + `authenticated` (safe columns).
- `categories`: SELECT to `anon` + `authenticated`; writes service-role only.
- `listings`: SELECT where `status = 'ACTIVE'` (anon + authenticated) OR
  `(select auth.uid()) = owner_id`; INSERT/UPDATE/DELETE own rows only.
- `listing_photos`: SELECT when parent listing is publicly readable or owned;
  INSERT/UPDATE/DELETE only by the listing's owner.
- `favorites`, `saved_searches`: fully member-owned (`(select auth.uid()) = user_id`)
  for all verbs.
- `storage.objects` (`listing-photos`, `avatars`): public read; authenticated
  write/update/delete only within the member's own `{auth.uid()}/…` path prefix.

`lat`/`lng`/`distanceMeters` contract is preserved.
