# SCR-022 — Separate Didit identity status from Stripe payout readiness

Status: Accepted
Date: 2026-08-23
Author: Codex (fethi-mobile issue #28)
DB reviewer: Atou4 (explicit instruction in-session to keep Stripe payouts separate and complete the Didit mobile integration)
Migration: none

## What changes

Two existing authenticated Edge Function contracts change without a schema,
enum, or RLS change:

- `didit-session-create` now requires `{ consent: true }`. The function records
  a server timestamp and consent-copy version in Didit session metadata before
  returning the hosted URL.
- `kyc-status` now treats `profiles.kyc_status` (written by the signed Didit
  webhook) as identity truth. It returns the latest verified Didit provider
  status for the current `kyc_session_id`, plus Stripe's independent
  `payoutsEnabled` boolean:
  `{ status, providerStatus, canRetry, payoutsEnabled, source }`.

`didit-webhook` also recognizes Didit's current exact `Kyc Expired` and
`Awaiting User` strings. The pre-existing `KYC Expired` spelling remains as a
compatibility alias.

## Why

Issue #28 requires the app to show pending, verified, rejected, expired, and
retry/resubmission states. The four-value `profiles.kyc_status` enum deliberately
collapses Didit's richer status vocabulary, so the detailed state is read from
the latest verified webhook event instead of widening the enum.

Stripe Connect remains mandatory for bank details and payouts, but its account
readiness must not overwrite Didit's identity result. A user can therefore be
identity-verified while still needing to configure Stripe payouts.

## RLS intent

No RLS change. Both functions require the caller's Supabase JWT and use the
service role only after resolving `auth.uid()`. A caller can retrieve only their
own profile/session and payout readiness. `didit_webhook_events` remains
service-role-only with no client policy.

## Edge Functions

- `POST didit-session-create`
  - Auth: user JWT.
  - Input: `{ consent: true, callback?, callbackMethod?, language? }`.
  - Returns: `{ url, sessionId, status }`.
  - Secrets remain backend-only: `DIDIT_API_KEY`, `DIDIT_WORKFLOW_ID`.
- `GET kyc-status`
  - Auth: user JWT.
  - Returns: `{ status, providerStatus, canRetry, payoutsEnabled, source }`.
  - Never trusts the mobile callback status.

## Rollback / compatibility

The `kyc-status` response is additive for callers that only read `status`.
Requiring consent on `didit-session-create` intentionally rejects older mobile
clients with `422 didit_consent_required`; production activation must therefore
deploy the updated mobile client before or with this function version.
