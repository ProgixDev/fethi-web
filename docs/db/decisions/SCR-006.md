# SCR-006 — `mark_thread_read` RPC (reset own unread counter)

Status: Proposed   <!-- Proposed | Accepted | Rejected | Superseded by SCR-XYZ -->
Date: 2026-06-25
Author: Dev B (mobile lane — TASK-007)
DB reviewer: web lead (flag for human ratification)
Migration: pending

## What changes

Additive, forward-only. One `SECURITY DEFINER` function. **Gap found while
building TASK-007:** SCR-003 made `threads` *no client UPDATE* (last_message /
unread are trigger-maintained), and the insert trigger only ever *increments*
the OTHER party's unread. **Nothing resets a participant's own unread to 0 when
they read the thread** — so `threadsApi.markRead` has no server artifact to call.

- `mark_thread_read(p_thread_id uuid) returns void`, `SECURITY DEFINER`,
  `search_path = public`, `EXECUTE` granted to `authenticated` (revoked from
  `PUBLIC`):
  - verifies the caller is a participant (`is_thread_participant(p_thread_id,
    auth.uid())` — the helper SCR-003 already added);
  - sets the caller's side to 0: `buyer_unread = 0` where `buyer_id = auth.uid()`,
    else `seller_unread = 0` where `seller_id = auth.uid()`, for that thread only;
  - no-op (no error) if the caller is not a participant.

No table/column/enum/RLS changes. The function is the *only* sanctioned writer of
the unread reset, keeping the SCR-003 "no client UPDATE on threads" invariant.

## Why

TASK-007 acceptance: "`unreadCount` and per-thread unread are accurate after
send/receive/**markRead**" and "recompute server-side on markRead." Without this
RPC the inbox unread badge only grows and never clears. The mobile seam already
calls it: `threadsApi.markRead` → `supabase.rpc('mark_thread_read', { p_thread_id })`,
and **swallows the error until this ships** (documented in `api.ts` + the
TASK-007 PR), so shipping this is non-breaking and purely additive.

## RLS intent

Function runs `SECURITY DEFINER` (bypasses RLS) but self-gates on
`is_thread_participant(p_thread_id, auth.uid())`, so a caller can only ever zero
*their own* unread on a thread they belong to. `EXECUTE` revoked from `PUBLIC`,
granted to `authenticated`.

## Edge Function (if any)

None — a Postgres RPC is sufficient (no external secrets, single-row update).

## Affected consumers

- Mobile: **TASK-007** (`threadsApi.markRead`, inbox unread badge). Unblocks the
  "accurate unread after markRead" acceptance criterion.
- Web: admin/messaging read models unaffected (read-only on these counters).
