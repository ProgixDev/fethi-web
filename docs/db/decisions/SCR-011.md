## What changes

Additive, forward-only. Introduces the **digital-entitlement** store consumed by
mobile TASK-015 (MyStreet+, custom-radius perk, listing boosts) delivered via
Apple In-App Purchase / Google Play Billing through **RevenueCat**.

This rail is kept **strictly separate** from the Stripe marketplace money rail
(SCR-009 `payments`/`payout_accounts`). Apple Guideline **3.1.1 / 3.1.5(a)**:
digital goods consumed in-app must go through store billing, and physical
marketplace goods must NOT use IAP — so the two rails never mix.

### New tables

1. **`app_entitlements`** — the CURRENT entitlement state per
   `(user_id, entitlement_key)`. Readable by the owning user; written ONLY by
   trusted store-validation logic (the RevenueCat webhook Edge Function, service
   role). A client-side "is plus" flag is a **cache only**, never the source of
   truth.
   - `id uuid PK`
   - `user_id uuid not null references profiles(id) on delete cascade`
   - `entitlement_key text not null` — RevenueCat entitlement id the app gates on
     (`plus`, `custom_radius`, `boost`)
   - `is_active boolean not null default false`
   - `product_id text`, `platform text`, `store text`, `period_type text`,
     `will_renew boolean`, `expires_at timestamptz` (null = lifetime),
     `latest_transaction_id text`, `metadata jsonb`
   - `created_at`/`updated_at timestamptz not null default now()`
   - **unique `(user_id, entitlement_key)`** — the webhook upsert target
   - index `app_entitlements(user_id, entitlement_key)`

2. **`app_store_transactions`** — append-only audit of every validated store
   transaction/event from the provider webhook. Written ONLY by the service
   role; readable own-row.
   - `id uuid PK`, `user_id uuid references profiles(id) on delete set null`
   - `platform text not null`, `transaction_id text not null`,
     `product_id text`, `entitlement_key text`, `event_type text`,
     `environment text`, `store text`, `price_cents int`, `currency text`,
     `purchased_at timestamptz`, `expires_at timestamptz`, `raw jsonb`,
     `created_at timestamptz not null default now()`
   - **unique `(platform, transaction_id)`** — idempotency guard against
     at-least-once webhook delivery

### RLS

Both tables: RLS enabled; a single **own-row SELECT** policy for `authenticated`
(`user_id = (select auth.uid())`). **No INSERT/UPDATE/DELETE policy** → all
client writes are RLS-denied; only the service role (RLS-bypassing, used by the
webhook Edge Function) mutates them. Mirrors the SCR-009 `payout_accounts`
trusted-write model.

## Edge Function (deployed separately, not part of the migration)

- **`revenuecat-webhook`** (`verify_jwt=false` — self-verifies a bearer token
  against `REVENUECAT_WEBHOOK_AUTH`): parses the RevenueCat event, records the
  transaction in `app_store_transactions` (deduped by `(platform,
  transaction_id)`), and upserts `app_entitlements` on `(user_id,
  entitlement_key)`. Revokes (`is_active=false`) on EXPIRATION / CANCELLATION-
  past-expiry / REFUND.

## Consumers / follow-ups

- **Unblocks:** mobile TASK-015. `entitlementsApi.mine()` reads
  `app_entitlements` own-row; feature gating (MyStreet+, custom radius, boosts)
  checks the server entitlement, not a client flag.
- **External prerequisites (NOT code):** a RevenueCat account + public SDK keys
  (`EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` / `_ANDROID_API_KEY`), the webhook auth
  secret (`REVENUECAT_WEBHOOK_AUTH`), and App Store Connect / Play Console
  products linked in RevenueCat. `react-native-purchases` needs a native build
  (not Expo Go), so the client purchase/restore wiring is a fast-follow once the
  account exists.
