# SCR-007 — Report rate-limit (per-reporter, server-side)

Date: 2026-06-28
Author: Dev (mobile lane — TASK-014 follow-up)
DB reviewer: web lead (flag for human ratification)
Migration: pending

## What changes

Additive, forward-only. One `SECURITY DEFINER` trigger function on `reports`.
SCR-005 created `reports` with insert-only RLS but **no rate-limit** (the note said
"enforced in the report Edge Function"); mobile now inserts reports **directly**
via Supabase (no Edge Function), so the cap has to live in the DB.

- `enforce_report_rate_limit()` — `BEFORE INSERT` trigger on `public.reports`,
  `SECURITY DEFINER` (so it can count the reporter's rows past the insert-only
  RLS). If the reporter already has **≥ 5 reports in the last hour**, it raises
  `RATE_LIMITED` (SQLSTATE `P0001`); otherwise the insert proceeds.
- Backed by the existing `reports(reporter_id, created_at desc)` index (SCR-005).

No table/column/enum/RLS-policy change. The function is a trigger (not a callable
RPC), so the generated types are unchanged.

## Why

Prevent report spam / abuse now that the client writes `reports` directly. The
mobile `reportsApi.create` maps the `RATE_LIMITED` error to its existing
`ApiError(code: 'RATE_LIMITED')`, which `ReportFlow` already surfaces as
"Trop de signalements — attends une heure." (the UI handler predates this).

## RLS intent

Unchanged. `reports` stays insert-only for `reporter_id = auth.uid()`, no client
SELECT. The trigger runs `SECURITY DEFINER` purely to count the reporter's recent
rows (which RLS would otherwise hide from the inserting user).

## Edge Function (if any)

None — a BEFORE INSERT trigger is sufficient; no external secrets.

## Affected consumers

- Mobile: **TASK-014** follow-up (`reportsApi.create` RATE_LIMITED mapping),
  **TASK-013** (reviews/reports moderation) later.
- Web: none (admin moderation reads are unaffected).

Pure addition of one trigger function. Dropping it just removes the cap (reports
still insert fine). No effect on the web app in production. Threshold (5/hour) is
a single literal — tune in a follow-up migration if needed.
