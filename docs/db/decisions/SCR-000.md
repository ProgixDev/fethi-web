Migration: none (process bootstrap, no schema change)

## What changes

No schema change. This SCR exists as the worked example of the format and to
record the decision that **`fethi-web` is the canonical owner of the shared
Supabase database**, with `fethi-mobile` as a consumer that files SCRs here.

## Why

Both apps target one Supabase project. Without a single owner and a change gate,
the two repos would write conflicting migrations and drift on enums/RLS. See
`../COORDINATION.md`. Establishes the SCR → migrate → regen types → sync → unblock
flow. Drives board task WEB-001 (web) and TASK-001 (mobile).
