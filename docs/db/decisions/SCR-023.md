# SCR-023 — Delete Didit verification data with account deletion

Status: Accepted
Date: 2026-08-23
Author: Codex (fethi-mobile issue #28)
DB reviewer: Atou4 (explicit instruction in-session to accept the DPA, use Unlimited retention, and proceed with release)
Migration: none

## What changes

The existing authenticated `account-delete` Edge Function now reads the
caller's `profiles.kyc_session_id`. When present, it deletes that verification
session through Didit's server-side API before anonymizing the local account.
It also clears `kyc_session_id` and `kyc_decision` from the tombstoned profile.

## Why

The approved Didit Console retention setting is Unlimited, so verification
inputs and outputs have no automatic expiry. Account deletion must therefore
explicitly remove the processor-held KYC session so the app does not report a
completed deletion while identity documents remain with Didit.

## RLS intent

No RLS change. `account-delete` already authenticates the caller and uses the
service role only for that caller's account. The Didit API key remains an Edge
Function secret and is never returned to the client.

## Edge Function contract

- `POST account-delete`
  - Auth and request/response shapes are unchanged.
  - If no KYC session exists, deletion proceeds as before.
  - Didit `204` and already-absent `404` both permit local deletion.
  - A missing Didit secret or any other provider failure stops deletion and
    returns an error; local data is not tombstoned first.

## Affected consumers

- Mobile account deletion UI: response shape unchanged.
- Mobile issue #28: closes the deletion lifecycle for Unlimited KYC retention.
- Web privacy policy: may accurately state that account deletion removes the
  associated Didit session.

## Rollback / compatibility

The mobile request and success response are unchanged. Rolling back removes
the external deletion guarantee and therefore also requires reverting the
corresponding privacy statement before serving the older function.
