## What changes

Additive, forward-only. Two DB changes backing the payment-review fixes **A5**
and **B3** (see the payment architecture review):

### A5 — `app_entitlements` out-of-order guard
- New column `app_entitlements.event_ts timestamptz` — the RevenueCat event's
  own logical timestamp.
- New `BEFORE UPDATE` trigger `app_entitlements_no_stale_update` (fn
  `app_entitlements_reject_stale`, SECURITY INVOKER): if the incoming write
  carries an older `event_ts` than the stored row, the UPDATE is skipped and the
  newer row is preserved. RevenueCat webhooks are not ordered, so a late
  `RENEWAL` arriving after a `CANCELLATION` must not clobber newer state.
- `revenuecat-webhook` now stamps `event_ts` from `event_timestamp_ms` on every
  entitlement upsert.

### B3 — atomic order pickup confirmation
- New fn `confirm_order_pickup(p_order_id uuid, p_actor uuid) returns orders`
  (SECURITY INVOKER, `search_path = public`). A single UPDATE flips only the
  caller's confirmation flag and derives `status`/`completed_at`, so two
  simultaneous confirmations can't lose one (the previous edge-function
  read-modify-write could). Guards party membership + non-terminal state.
- **EXECUTE revoked from `public`/`anon`/`authenticated`, granted only to
  `service_role`** — it is NOT a public RPC; only the `orders-transition` Edge
  Function (service role) calls it.

## Why SECURITY INVOKER (not DEFINER)

The RPC is executed by the Edge Function with the **service role**, which already
bypasses RLS — no elevated `DEFINER` context is needed. Keeping it INVOKER plus a
`service_role`-only EXECUTE grant avoids the "SECURITY DEFINER in public is a
public API" trap and the caller-supplied-`p_actor` spoofing risk (a client can't
call it at all).

## Consumers

- Web-only DB/function change. Mobile reacts by vendoring the regenerated types
  (adds `app_entitlements.event_ts`); no mobile code change — the affected Edge
  Functions (`payments-create-intent`, `stripe-webhook`, `revenuecat-webhook`,
  `orders-transition`) keep their existing request/response contracts.

## Related edge-function fixes shipped alongside (no schema change)

- **B1 (partial):** `payments-create-intent` no longer accepts a client
  `amountCents`/`currency` — the charge is always `order.amount_cents` in EUR.
- **B2:** `payments-create-intent` passes a Stripe `idempotencyKey` + does a
  conditional attach so a concurrent double-call can't orphan a PaymentIntent.
- **A4:** `stripe-webhook` claims → processes → **rolls back the dedup claim on
  failure** so a failed handle isn't marked processed and silently dropped on
  retry.

## Verification (live, at apply time)

- `event_ts` column present; stale UPDATE (older `event_ts`) is a no-op, newer
  applies.
- `confirm_order_pickup` not executable by `authenticated`; two confirmations
  converge to COMPLETED with both flags set.
