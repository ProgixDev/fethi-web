## What changes

Additive, forward-only. Completes the trust-&-safety + store-compliance backend
(WEB-008). `reports` and `blocked_users` already shipped in **SCR-005** (and
**SCR-007** added the per-reporter report rate-limit), so this SCR does **not**
re-create them. It adds:

1. **Table `reviews`** — order-gated public reputation (mobile `ReviewResponse`).
   - `id uuid PK default gen_random_uuid()`
   - `order_id uuid not null references orders(id) on delete cascade`
   - `author_id uuid not null references profiles(id) on delete cascade`
   - `target_user_id uuid not null references profiles(id) on delete cascade`
   - `rating smallint not null check (rating between 1 and 5)`
   - `comment text check (<= 2000 chars)`
   - `created_at timestamptz not null default now()`
   - `unique (author_id, order_id, target_user_id)`; `check (author_id <> target_user_id)`.
   - indexes: `(target_user_id, created_at desc)`, `(order_id)`.

2. **Column `profiles.deleted_at timestamptz`** (nullable) — account-deletion
   tombstone, stamped by the `account-delete` Edge Function.

3. **Trigger function `recompute_profile_review_stats()`** — `AFTER INSERT/UPDATE/
   DELETE` on `reviews`, `SECURITY DEFINER`, recomputes `profiles.rating` (avg) +
   `profiles.reviews_count` for the reviewed user.

4. **Edge Functions** (authored in `supabase/functions/`, deploy pending — CLI
   needs Docker, unavailable here; same posture as SCR-005's functions):
   - `account-delete` — `POST /me/deletion`
   - `account-export` — `POST /me/export`
   - `kyc-status` — `GET /me/kyc-status`
   (deployed to the live project via `supabase functions deploy` — no Docker needed.)

## Why

- **Reviews** back fethi-mobile **TASK-013** (post-transaction reputation) and the
  already-shipped public profile page (`reviewsApi.listForUser`).
- **Account deletion/export** are App Store Review **5.1.1(v)** + Google Play
  data-safety hard blockers; the mobile client surface ships behind the api.ts
  seam (TASK-014) and was waiting on these functions (SCR-005 proposed them but
  only the tables were migrated).
- **kyc-status** gives mobile + the future admin KYC dashboard (WEB-012) a single
  mapped read of Connect onboarding state.

Cross-repo map (`docs/db/COORDINATION.md` §6) labels this **WEB-008**.

## RLS intent

- `reviews` **SELECT**: public (`to anon, authenticated using (true)`) — reputation
  is public per product policy.
- `reviews` **INSERT** (`to authenticated`): `author_id = (select auth.uid())`,
  `author_id <> target_user_id`, and an `EXISTS` gate requiring a **COMPLETED**
  order where the caller and the target are the two parties (buyer↔seller). This
  enforces order-gating + membership + correct counterparty in one predicate.
- `reviews` has **no UPDATE/DELETE policy** → immutable from clients; moderation
  retraction is service-role only (the aggregate trigger reconciles stats).
- `profiles.deleted_at` is written only by the service-role Edge Function; no new
  client policy (profiles RLS unchanged).

## Edge Function (if any)

All three: user JWT in; service-role client for privileged work; error bodies are
`{ code, message }` (mobile `throwApiError` reads `body.code`). Secrets are Edge
secrets only (`SUPABASE_*`, optional `STRIPE_SECRET_KEY`, `RESEND_API_KEY`) — never
`NEXT_PUBLIC_*` / `EXPO_PUBLIC_*`.

- **`account-delete`** (`POST /me/deletion`): blocks with `409 { code:
  'DELETION_BLOCKED' }` when the caller has an active order (`AWAITING_PICKUP` /
  `HANDOFF_PENDING` / `DISPUTED`) on either side; else anonymises profile PII,
  archives listings, stamps `deleted_at`, and **bans the auth user** (deleting a
  user does NOT invalidate live JWTs — Supabase security checklist). The profile
  row is kept (orders FK is `ON DELETE RESTRICT`). Idempotent. Returns
  `{ status: 'DELETED' }`.
- **`account-export`** (`POST /me/export`): assembles the caller's rows across the
  schema into a JSON archive; hands off to the mailer when `RESEND_API_KEY` is
  set, else returns `{ status: 'QUEUED', deliveryEmail }` (202).
- **`kyc-status`** (`GET /me/kyc-status`): self-scoped (no IDOR). Maps Stripe
  Connect `payout_accounts` state → `KycStatus` when present; otherwise falls back
  to `profiles.kyc_status` (`source: 'profile'`). Collapses web-only `REVIEW` to
  `PENDING`. Never 500s on missing Stripe config / table.

## Affected consumers

- Mobile: **TASK-013** (`reviewsApi` — reviews), **TASK-014** (`meApi.requestDeletion`
  / `requestExport`, KYC). Client surface already shipped behind the seam.
- Web: admin moderation (`reports`) unaffected; **WEB-012** (KYC dashboard) will
  consume the Connect mapping once WEB-006 lands `payout_accounts`.

## Rollback / compatibility

Fully additive — one new table, one nullable column, one trigger fn, three new
Edge Functions. No existing column/enum/policy is changed, so the web app in
production is unaffected. Rolled back, the mobile client seam degrades gracefully
(reviews list empty, deletion/export calls surface a clean network/404 error and
touch no data). The `reviews` INSERT policy depends on the existing `orders`
table + `order_status` enum (SCR-003); both are merged.
