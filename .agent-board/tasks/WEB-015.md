Status: Done
Priority: P2

## Purpose
Ship the public marketing site plus a waitlist / referral capture — the only fully public, non-admin surface. The buffer task either dev can pull when their lane is blocked.

## Scope
- Marketing pages under `src/app/(marketing)`.
- Waitlist signup + referral code capture.
- SEO / metadata.
- Where it touches data, go behind `src/lib/api.ts`.
- If persisting waitlist to the shared DB, file an SCR for a `waitlist` table (RLS: public insert, staff read); otherwise use a lightweight provider.

## Acceptance Criteria
- [ ] Marketing pages render and are publicly accessible (no auth).
- [ ] Waitlist signup + referral capture works.
- [ ] SEO/metadata present on marketing pages.
- [ ] If persisted to shared DB: RLS is public-insert / staff-read and hardened.
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- Routes/UI under `src/app/(marketing)`.
- Flow docs: `docs/features/marketing/{public_marketing_site_flow,waitlist_referral_flow}.md`.
- Uses the recent Next.js metadata API — read `node_modules/next/dist/docs/` before writing route/handler/metadata code.
- Data access behind `src/lib/api.ts` where it touches the backend.

## Coordination
If waitlist persists to the shared DB, file an SCR (public-insert RLS, staff read), regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, and copy types to fethi-mobile in the same PR. Otherwise: No shared-DB change — no SCR required. Unblocks mobile: none.

## Edge Cases
- Duplicate waitlist email.
- Referral abuse / self-referral.
- Spam submissions.
- Public RLS insert hardening (rate limiting, no read-back of other rows).
