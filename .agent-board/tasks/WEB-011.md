# WEB-011 — Reports / moderation review workflow

Status: Done
Priority: P1
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev B
Schema: none new (consumes the `reports`/`blocked_users` schema already shipped by **SCR-005**, the store-compliance SCR — NOT the full WEB-008 bundle; file an SCR only if you add a moderation-action/audit table)

## Purpose
Give moderators a queue to review reports and take action (dismiss, warn, hide content, suspend user), wired to the `reports` schema that WEB-008 owns. Supports store-compliance UGC moderation.

## Scope
- Report queue: list + filter by `targetType` (LISTING/USER/THREAD/MESSAGE) and `status` (OPEN/REVIEWING/ACTIONED/DISMISSED).
- Report detail with target context: resolve and render the reported listing / user / thread / message.
- Staff actions transitioning report status OPEN→REVIEWING→ACTIONED/DISMISSED.
- Linked enforcement: hide listing / suspend user / block — executed via a service-role route handler (never the browser key), audited.
- All data access behind `src/lib/api.ts` (`reportsApi`).
- File an SCR only if a new moderation-action / audit table or enum is required.

## Acceptance Criteria
- [ ] Moderators can list and filter reports by target type and status.
- [ ] Report detail shows the underlying target's context.
- [ ] Status transitions and linked enforcement actions persist and are audited.
- [ ] Enforcement runs through a service-role route handler, not client-side keys.
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- Routes/UI under `src/app/(admin)/(authed)/moderation`.
- Consumes `reportsApi` (`list`/`get`/`setStatus`) in `src/lib/api.ts`; `ReportStatus` + `ReportTargetType` enums originate from WEB-008.
- Enforcement (suspend/ban/hide) needs service-role; use a Next.js server route handler — read `node_modules/next/dist/docs/` before writing route/handler code.
- Reuse `listingsApi.setStatus` / user-status updates for enforcement where they already exist.

## Coordination
Uses WEB-008 (`reports`/`blocked_users`). No shared-DB change unless you add a moderation-action/audit table — in that case file an SCR, regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, and copy types to fethi-mobile in the same PR. Unblocks mobile: none directly (mobile users feel the enforcement; relates to mobile TASK-014).

## Edge Cases
- Report on a deleted/archived target (target no longer resolvable).
- Duplicate reports against the same target — group or de-dupe.
- Action idempotency: re-applying an enforcement must not double-apply.
- Moderator vs admin permission boundaries on enforcement actions.
- Audit trail completeness (who acted, when, what transition).
