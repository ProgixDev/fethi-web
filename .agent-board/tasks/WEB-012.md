# WEB-012 — KYC verification dashboard (Stripe Connect status)

Status: Backlog
Priority: P1
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev B
Schema: none (reads Stripe Connect status via WEB-006 Edge Functions; SCR-NNN only if a local KYC-status cache table is added)

## Purpose
Let staff view seller KYC / payout-onboarding status — sourced from Stripe Connect Express, which runs the actual KYC — and follow up on incomplete accounts. No custom KYC capture in this repo.

## Scope
- List sellers with their Connect account state: onboarded / restricted / pending / requirements due.
- Detail view pulling Stripe Connect account status (incl. `requirements`) via the WEB-006 service-role Edge Function.
- Resend onboarding link action (Stripe-hosted Connect flow).
- All data access behind `src/lib/api.ts` (`kycApi`).
- If caching KYC status locally for perf/listing, file an SCR for the cache table.

## Acceptance Criteria
- [ ] Sellers list shows accurate Connect account state.
- [ ] Detail view surfaces Stripe `account.requirements` (currently due / past due / pending verification).
- [ ] Resend-onboarding-link action works against the Connect Express flow.
- [ ] Stripe access is via the WEB-006 service-role Edge Function only (no STRIPE_* keys client-side).
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- Routes/UI under `src/app/(admin)/(authed)/kyc`.
- Consumes `kycApi` in `src/lib/api.ts`; align with the `KycStatus` enum (UNVERIFIED/PENDING/REVIEW/VERIFIED/REJECTED) and map Stripe Connect `account.requirements` onto it.
- Status comes from Stripe via WEB-006 Edge Functions — STRIPE_* secrets live in Edge Functions only.
- Read `node_modules/next/dist/docs/` before writing any route/handler code.

## Coordination
Reads via WEB-006 Edge Functions. No shared-DB change unless you add a local KYC-status cache table — then file an SCR, regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, copy types to fethi-mobile in the same PR. Unblocks mobile: none (mobile sellers onboard via the Stripe-hosted Connect flow from TASK-011).

## Edge Cases
- Stripe API error / timeout — degrade gracefully, do not block the page.
- Account becomes restricted mid-review.
- Requirements past due (currently_due vs past_due distinction).
- No seller Connect accounts yet (empty state).
