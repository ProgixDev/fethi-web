# WEB-016 — Server-authoritative order pricing

Status: Review
Priority: P0
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev A
Schema: none (uses existing `orders`/`listings`; SCR only if a fee/pricing column is added)

## Purpose
Close the order-amount integrity hole (payment review **B1-full**): `orders-create`
currently trusts a client-supplied total (`amountCentsOverride` / checkout
`totalCents`) for direct buys, so a buyer can create an order — and therefore a
PaymentIntent — for an arbitrary amount (e.g. 1 cent for a 100 € listing). The
server must be the single pricing authority.

> Partially mitigated in SCR-012: `payments-create-intent` already charges
> `order.amount_cents` only (the *payment* can't diverge from the *order*). This
> task fixes the remaining gap — the *order amount itself* must be server-computed.

## Scope
- `orders-create` recomputes the order total from `listings` pricing + the order
  params, and ignores any client-supplied total:
  - **VENTE** (sale): `price_cents` (+ platform fee).
  - **LOCATION** (rental): `price_per_day_cents × days(start,end)` (+ fee); record
    `deposit_cents` separately (held, not charged now).
  - **SERVICE**: `hourly_rate_cents × hours` or `flat_rate_cents` (+ fee).
- Persist `amount_cents` (server-computed) and `fee_cents` on the order.
- Change the create contract so the client passes **params** (rentalStart/End,
  hours), not a final total. Update mobile `ordersApi.create` + the three checkout
  screens (`payment/checkout/{,service/,rental/}[listingId]`) accordingly.
- The offer path is already safe (uses `offer.amount_cents`, gated on ACCEPTED).

## Acceptance Criteria
- [ ] `orders-create` ignores any client total; `order.amount_cents` is derived
      server-side from listing pricing + params for all three listing types.
- [ ] A tampered client total cannot change the order or the charged amount.
- [ ] `fee_cents` recorded; rental `deposit_cents` recorded and excluded from the
      now-charged total.
- [ ] Existing offer-based orders unchanged.
- [ ] Mobile checkout screens pass params; display total matches server total.
- [ ] `npm run typecheck` + mobile `pnpm typecheck` pass.

## Technical Notes
- Fee model must match the client's current 5% (`Math.round(subtotal*0.05)`) until
  a product decision changes it — keep one canonical formula server-side.
- Cross-repo: same PR/coordination as the mobile contract change.
- Read `node_modules/next/dist/docs/` before writing route/handler code.
