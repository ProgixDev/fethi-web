# WEB-004 — Admin auth + staff RBAC + route protection

Status: Backlog
Priority: P0
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev B
Schema: SCR-002 (staff_roles / admin claims + RLS)

## Purpose
Protect the `(admin)/(authed)` routes with Supabase Auth plus a staff role model (admin / moderator / finance / support), enforced server-side — never from user-editable metadata.

## Scope
- Propose SCR-002 (Accepted before merge) for staff role storage: a `staff_users` / roles table (or a trusted app-metadata claim set only by service role) + RLS/policies.
- Wire login / forgot-password / reset-password (already scaffolded under `(admin)`).
- Add a server-side route guard for `(admin)/(authed)`; role-gated nav; sign-out.
- Authorization must NOT be read from `user_metadata` (user-editable) — only from the trusted staff store / app-metadata claim.

- [ ] `(admin)/(authed)` routes are guarded server-side; non-staff users are rejected.
- [ ] Login / forgot-password / reset-password flows work; sign-out clears the session.
- [ ] Nav is role-gated; authorization never derives from `user_metadata`.
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- `@supabase/ssr` server guard in `src/app/(admin)/layout.tsx` + `src/app/(admin)/(authed)/layout.tsx`.
- `docs/db/COORDINATION.md` rule: do not authorize from `user_metadata`.
- Service-role is used only for cross-user staff actions in server route handlers / Edge Functions.
- This is a recent Next.js with breaking changes — read `node_modules/next/dist/docs/` before writing layout/route-guard/middleware code (see AGENTS.md).

## Coordination

## Edge Cases
- Session expiry mid-use (guard must re-check, not trust a stale cookie).
- Non-staff authenticated user hits an admin URL directly (must be blocked server-side).
- Role downgrade mid-session (next request reflects new role).
- Cross-user staff actions must use service role, not the caller's RLS context.
