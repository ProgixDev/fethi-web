# WEB-014 — Analytics & reporting read models

Status: Done
Priority: P2
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev B
Schema: none (read-only views/aggregations; SCR-NNN only if you add materialized views / aggregate tables)

## Purpose
Power the analytics dashboards (engagement, geo, listings, marketplace, users, reports) with real server-side aggregations instead of client-side fixtures.

## Scope
- Server-side aggregation queries or read-only Postgres views feeding the `analytics/*` routes.
- Charts via recharts.
- Date-range filters.
- All data access behind `src/lib/api.ts` (`analyticsApi`).
- Prefer read-only SQL views; if adding materialized views / aggregate tables for performance, file an SCR.

## Acceptance Criteria
- [ ] Each analytics route renders real aggregated data (no fixtures).
- [ ] Date-range filters drive the queries.
- [ ] Charts render correctly for representative ranges.
- [ ] Aggregations respect RLS/service-role access correctly (no data leak).
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- Routes/UI under `src/app/(admin)/(authed)/analytics/{engagement,geo,listings,marketplace,reports,users}`.
- Consumes/extends `analyticsApi` in `src/lib/api.ts`; aggregate from `profiles`/`listings`/`orders`/`reviews`.
- Consider indexes for heavy queries — defer to a perf SCR rather than adding ad hoc.
- For aggregate reads vs RLS, use a security-definer view or careful service-role read.
- Read `node_modules/next/dist/docs/` before writing any route/handler code.

## Coordination
Read-only by default — No shared-DB change — no SCR required. If you add materialized views or aggregate tables, file an SCR, regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, and copy types to fethi-mobile in the same PR. Unblocks mobile: none.

## Edge Cases
- Empty date ranges (no rows).
- Expensive full-table scans on large datasets.
- Timezone handling in date bucketing.
- RLS vs aggregate reads — security-definer view or service role used deliberately.
