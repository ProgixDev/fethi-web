## Purpose
Own notifications storage and server-side push dispatch, consumed by mobile (in-app feed + Expo push) and the admin communications surface later.

## Scope
- Author SCR-005 (notifications + device_push_tokens + dispatch Edge Function) and get it Accepted before coding the migration.
- Migration: `notifications` table with own-row RLS (a user reads only their own); `device_push_tokens` table keyed by user + token.
- Enable Supabase Realtime on `notifications` so mobile gets live in-app updates.
- Edge Function: dispatch push via Expo on domain events (message / offer / order) using the service role + a server-only push provider secret.
- `NotifKind` enum (`MESSAGE`/`OFFER`/`BOOKING_REQUEST`/`LISTING_SOLD`/`ORDER_UPDATE`/`REVIEW`/`PAYOUT`/`SYSTEM`) must match mobile `api.ts`.
- Regenerate types + MOBILE-SYNC-NOTES entry + copy types to mobile in the same PR.

## Edge Cases
- Dead / expired push tokens → prune on Expo "DeviceNotRegistered" receipts.
- Duplicate token rows for the same device → upsert / dedupe.
- Unread-count drift between in-app and push.
- Push permission denied on device → still store in-app notification.
- Fan-out cost on high-volume events → batch dispatch.
