## Purpose
Author the transactional core — messaging, offers, and orders — with participant-scoped RLS and server-enforced state transitions via Edge Functions that both apps call. Raw clients never mutate order/offer state directly.

## Edge Cases
- Double-accept of an offer (second call rejected by invariant).
- Expired offer accepted (must reject).
- Duplicate order from a retry (deduped by `Idempotency-Key`).
- Confirm-pickup / cancel attempted by the wrong party (rejected).
- Cancel after the order is COMPLETED (rejected).
- RLS leak to a non-participant (must read nothing).
