## Purpose
Author the transactional core — messaging, offers, and orders — with participant-scoped RLS and server-enforced state transitions via Edge Functions that both apps call. Raw clients never mutate order/offer state directly.

## Scope
- Propose SCR-003 (Accepted before merge), then author the migration.
- Tables: `threads`, `messages` (+ `message_attachments`), `offers`, `orders` (+ `order_events`).
- RLS: reads scoped to buyer / seller / thread participants only.
- Edge Functions for state transitions enforcing invariants + an `Idempotency-Key`: offer accept/reject/withdraw; order create/confirm-pickup/cancel.
- Enable Realtime for `messages`, narrowed by `thread_id`.
- Enums must match mobile `api.ts` exactly: `OfferStatus`; order status `AWAITING_PICKUP` / `HANDOFF_PENDING` / `COMPLETED` / `CANCELLED` / `REFUNDED` / `DISPUTED`.
- Regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, copy types to fethi-mobile — same PR.

## Edge Cases
- Double-accept of an offer (second call rejected by invariant).
- Expired offer accepted (must reject).
- Duplicate order from a retry (deduped by `Idempotency-Key`).
- Confirm-pickup / cancel attempted by the wrong party (rejected).
- Cancel after the order is COMPLETED (rejected).
- RLS leak to a non-participant (must read nothing).
