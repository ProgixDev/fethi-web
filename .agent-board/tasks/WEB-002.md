# WEB-002 — Admin app architecture: data-access seam, env, supabase client

Status: Done
Priority: P0
Project: MyStreet Web
Milestone: 10-day production launch

Schema: none

## Purpose
Establish the admin app's data-access seam and Supabase client (browser + server via `@supabase/ssr`) plus env, keeping `src/lib/api.ts` as the stable boundary so screens never depend on Supabase directly.

## Scope
- Add `src/lib/supabase/client.ts` (browser client) and `src/lib/supabase/server.ts` (server client via `@supabase/ssr` with cookie handling).
- Add `.env.example` with `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and server-only `SUPABASE_SERVICE_ROLE_KEY` (used only in route handlers / Edge Functions — never in client code).
- Confirm `src/lib/api.ts` remains the seam; do not make screens import Supabase directly.
- Set up a repository-layer pattern for admin pages that sits behind the `api.ts` seam.
- Read `node_modules/next/dist/docs/` for the current Next.js data-fetching and route-handler conventions before writing any of this.

## Acceptance Criteria
- [ ] `src/lib/supabase/client.ts` and `src/lib/supabase/server.ts` exist with the SSR browser/server split.
- [ ] `.env.example` lists the three vars; service role is documented as server-only.
- [ ] Service-role key never appears in any `NEXT_PUBLIC_*` or client-bundle path.
- [ ] `src/lib/api.ts` is preserved as the seam; a repository-layer pattern is in place behind it.
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- `@supabase/ssr` server/client split; server client manages cookies/session in server components and route handlers.
- Admin routes live under `src/app/(admin)/(authed)`.
- Service-role key is read only in server route handlers / Edge Functions; client uses `NEXT_PUBLIC_*` only.
- This is a recent Next.js with breaking changes — read `node_modules/next/dist/docs/` before writing route/handler/server-component code (see AGENTS.md).
- Reads against real tables only exist once WEB-003 ships; build the seam against the typed contract / mocks until then.

## Edge Cases
- Service-role key accidentally bundled to the client (must stay server-only).
- Cookie/session handling broken in server components (SSR client misconfigured).
- Required env vars missing → fail fast with a clear error.
