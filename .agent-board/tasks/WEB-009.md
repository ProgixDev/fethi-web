# WEB-009 — User management (list/search/suspend/ban) wired to Supabase

Status: Backlog
Priority: P1
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev B
Schema: none (uses profiles + staff actions from WEB-003/WEB-004; if a ban/audit table is needed, file an SCR)

## Purpose
Wire the admin user-management screens to real Supabase data with staff-gated suspend/ban/reactivate actions, replacing fixtures behind the existing `src/lib/api.ts` seam.

## Scope
- List / search / filter users with server-side pagination via `@tanstack/react-table`.
- User detail view.
- Suspend / ban / reactivate via a staff-gated server route handler / Edge Function (service role, audited).
- Keep everything behind `src/lib/api.ts` (`usersApi`); swap implementation, keep interfaces; replace fixtures.
- If suspend/ban needs a status enum or audit table not already in WEB-003, file an SCR (do not change schema silently).

## Acceptance Criteria
- [ ] User list supports server-side pagination, search, and status/KYC/neighborhood filters from real data.
- [ ] Suspend/ban/reactivate actions run only for staff, via the service role, and are audited.
- [ ] Fixtures are removed; the screens consume `usersApi`.
- [ ] `UserStatus` values stay `ACTIVE`/`PENDING`/`SUSPENDED`/`BANNED`.
- [ ] `npm run typecheck` passes.
- [ ] No new `npm run lint` errors in touched files.

## Technical Notes
- Read `node_modules/next/dist/docs/` before writing any route/handler code — this Next.js has breaking changes.
- Routes: `src/app/(admin)/(authed)/users`.
- Seam: `usersApi` in `src/lib/api.ts` (`list`, `meta`, `exportXlsx`, `invite`); `AdminUserListItem`/`UserFilters`/`PageResponse` shapes already defined.
- Staff action mutates via the service role only — never expose service-role keys client-side.

## Coordination
No new shared-DB change expected — uses WEB-003 schema + WEB-004 RBAC. If you add a ban-status enum or audit table, file an SCR and update sync notes + regenerate types in the same PR. Unblocks mobile: none.

## Edge Cases
- Ban actor must be staff (RBAC-gated).
- Banning self → blocked.
- Reactivating an already-active user → no-op / clear feedback.
- Search input safety (no injection; parameterized).
- Large user lists → server-side pagination, no full-table client load.

## Dependencies

- External: none.
