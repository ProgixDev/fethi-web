# WEB-003 — Core schema + RLS: profiles, listings, categories, favorites, saved_searches

Status: Done
Priority: P0
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev A
Schema: SCR-001 (creates profiles / listings / categories / listing_photos / favorites / saved_searches + RLS)

## Purpose
Author the core marketplace schema and RLS that BOTH apps depend on — the single biggest cross-repo unblock. Profiles, categories, listings, photos, favorites, and saved searches with safe public reads and owner-scoped writes.

## Scope
- Propose SCR-001 in `docs/db/decisions/`, get it Accepted, then author the migration.
- Tables: `profiles` (`id` references `auth.users`; plus a `public_profiles` view exposing only safe fields), `categories`, `listings` (+ `listing_photos`), `favorites` (unique `user_id` + `listing_id`), `saved_searches`.
- RLS: public reads of ACTIVE listings and public profile fields; owners read/write their own rows; `favorites` / `saved_searches` are own-row only.
- Indexes per migration plan: listings on status/type/category, owner+status, geo; favorites unique index.
- Storage buckets: `avatars` and `listing-photos` with appropriate policies.
- Regenerate types (`npm run db:types`), update `docs/MOBILE-SYNC-NOTES.md`, copy types to fethi-mobile — all in the same PR.

## Technical Notes
- References: `docs/db/COORDINATION.md` §6; migration plan sections "Identity And Profile" and "Listings And Discovery"; the listing/category/profile shapes in `src/lib/api.ts`.

## Edge Cases
- Public vs private profile field leakage (the view must expose only safe fields; RLS must not leak private columns).
- Non-ACTIVE listings visible to the public (visibility must be ACTIVE-only for anon/non-owner).
- Geo index choice (PostGIS vs lat/lng bounding-box) — pick one and document in SCR.
- Enum vocabulary drift vs mobile `api.ts` (`ListingType`, `ListingStatus`) — must match exactly.
