## Resolution (done 2026-07-27, Edge-only — no SCR)
New Edge Function `connect-dashboard-link` (POST, user-JWT, `verify_jwt` on): looks up the
caller's `payout_accounts.stripe_account_id`, refreshes the account from Stripe (syncs
`onboarding_status`/`payouts_enabled`/`details_submitted`, same as `connect-onboarding`),
then `stripe.accounts.createLoginLink` → `{ url }`. Guards return mapped codes, never a 500:
`503 stripe_unconfigured`, `409 no_connect_account`, `409 onboarding_incomplete` (login links
require `details_submitted`). No balance/bank data is stored or proxied — only the link is
returned. Deployed live via Management API (v1, ACTIVE, verify_jwt); probed 401 unauth (edge
JWT gate enforced). `edge-functions.json` appends the slug + vendored into mobile;
`MOBILE-SYNC-NOTES.md` updated. Mobile follow-up landed in the same batch: `connectApi.
dashboardLink()` added and the payouts "Gérer sur Stripe" CTA (enabled accounts) now opens the
real Express dashboard, falling back to `startOnboarding()` on the two 409 codes.

## Purpose
Mobile TASK-019 removed the fabricated seller balance / in-transit / lifetime
figures and the fake payouts list from `payouts/index.tsx`. With Stripe Connect
Express, Stripe owns the balance, payouts, transactions, bank account, and payout
schedule — the app must not replicate any of it. The standard way to surface it is
a **Stripe Express dashboard login link** (`stripe.accounts.createLoginLink`),
which opens the seller's own hosted dashboard (balance + payouts + history + bank +
schedule) with no regulated data touching our systems.

Right now the mobile "Gérer mes versements sur Stripe" CTA falls back to
`connectApi.startOnboarding()` (an account link for updating details) because no
login-link function exists. That works for onboarding/updates but does not show
balance/history.

## Scope
- New Edge Function `connect-dashboard-link`: user-JWT auth, looks up the caller's
  `payout_accounts.stripe_account_id`, calls `stripe.accounts.createLoginLink`, and
  returns `{ url }`. Guard: only for `ENABLED`/`payouts_enabled` accounts (login
  links require a completed Express account) — otherwise return a code the app maps
  to "finish onboarding first".
- Graceful when Stripe is unconfigured (`503 stripe_unconfigured`), consistent with
  the other payment functions.
- Append the slug to `supabase/functions/.../edge-functions.json` (the manifest the
  mobile coordination gate reads) in the same PR, and note it in
  `docs/MOBILE-SYNC-NOTES.md`. No schema change → no SCR needed (Edge-only).
- Mobile follow-up (separate, gated on this): `connectApi.dashboardLink()` →
  `connect-dashboard-link`; point the "Gérer sur Stripe" CTA at it; optionally show
  a real balance snapshot if a balance endpoint is added later.
