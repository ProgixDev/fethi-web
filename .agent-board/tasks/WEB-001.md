# WEB-001 — Shared DB contract + coordination protocol (supabase home, types, SCR, CI guard)

Status: Done
Priority: P0
Project: MyStreet Web
Milestone: 10-day production launch
Owner: Dev A
Schema: none (process + tooling)

## Purpose
Stand up the shared Supabase backend home in this repo and the coordination tooling so every DB change flows through an SCR and the generated types contract. This is the foundation that unblocks every backend task here AND mobile's consumer setup.

## Scope
- Create `supabase/` with `migrations/`, `functions/`, `seed.sql`, and `config.toml`.
- Add `npm run db:types` that runs `supabase gen types typescript` into `src/lib/database.types.ts`, with a version-hash header at the top of the generated file.
- Wire the SCR workflow: reference the already-existing `docs/db/COORDINATION.md`, `docs/db/decisions/SCR-TEMPLATE.md`, and `docs/db/decisions/` (do not recreate them).
- Add CI workflow `.github/workflows/db-drift.yml` that regenerates types and fails on any diff against the committed `src/lib/database.types.ts`.
- Document the type-vendoring step that copies `src/lib/database.types.ts` into `fethi-mobile/src/shared/types/database.types.ts`.
- Pin the Supabase CLI version plus `@supabase/supabase-js` and `@supabase/ssr` in `package.json`.

## Technical Notes
- Supabase CLI for `gen types` and local stack; `@supabase/ssr` for Next server clients (used by WEB-002).
- `docs/db/COORDINATION.md` §2 is the source-of-truth table — keep paths consistent with it (canonical types at `src/lib/database.types.ts`).
- This is a recent Next.js with breaking changes — read `node_modules/next/dist/docs/` before writing any route/handler/config code (see AGENTS.md).
- No migration is authored in this task; the directory and tooling only.

## Coordination
This task ESTABLISHES the protocol; no schema change yet, so no SCR is required. Unblocks mobile: TASK-001 (mobile consumer setup pairs with this). Once a real schema task ships (WEB-003+), the same PR must regenerate types, update `docs/MOBILE-SYNC-NOTES.md`, and copy types to fethi-mobile — this task builds the rails for that.

## Edge Cases
- `SUPABASE_PROJECT_ID` / project-ref env missing → `db:types` and CI should fail with a clear message.
- Types drift on CI (someone changed DB without committing types) → CI fails on `git diff`.
- Supabase CLI not installed locally → document install + pinned version so devs match CI.
