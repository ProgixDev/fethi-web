# WEB-018 — Ratify the calling decision (schema for `calls`, or record the cut)

## Resolution (2026-07-25) — CUT for v1
Decision recorded in `docs/adr/0002-cut-in-app-calling-for-v1.md`: cut calling for v1
(messaging covers contact; a real build is multi-day cross-repo work + a media-relay
vendor). Mobile executed the cut in TASK-021 (call screen, Jitsi embed, `callsApi`, and
both entry points removed). No schema change. If revived, build on Supabase Realtime and
file an SCR for the `calls` table then.
Project: MyStreet Web (DB owner)
Milestone: 10-day production launch
Owner: Dev A

## Purpose
The mobile app ships a full in-app calling surface (`callsApi`, `src/app/call/[id].tsx`,
a Jitsi embed) that talks to the **retired HTTP backend**. No `calls` table exists in
SCR-001…SCR-013, none is proposed, and the mobile board had no task for it until
TASK-021. As schema owner this repo has to close the question either way — an
undecided feature is how a dead surface survives to submission.

## Scope
- Decide with the product owner: cut calling for launch, or build it.
- **If cut**: record it as a scoping decision — a short ADR in `docs/adr/` stating
  calling is out of scope for v1 and why (messaging covers contact; media relay is
  an unbudgeted external dependency). Note in `docs/MOBILE-SYNC-NOTES.md` so mobile
  can execute TASK-021 branch (a) without re-litigating.
- **If build**: file an SCR for `calls` — participant-scoped RLS mirroring
  `is_thread_participant`, a `call_status` enum (RINGING/ACCEPTED/DECLINED/ENDED/MISSED),
  Realtime enabled for incoming-call delivery (the mobile client currently *polls*,
  which must not be carried forward), and an Edge Function for initiate/transition
  with idempotency. Separately decide the media layer — self-hosted Jitsi vs a hosted
  provider — and price it; that is another vendor account and another cost line.

## Acceptance Criteria
- [ ] A decision exists in writing (ADR or SCR), not an open question.
- [ ] If build: SCR merged, migration applied, types regenerated, `edge-functions.json`
      updated, `MOBILE-SYNC-NOTES.md` entry written — all in the same PR.
- [ ] If cut: ADR merged and the mobile board's TASK-021 branch is unambiguous.
